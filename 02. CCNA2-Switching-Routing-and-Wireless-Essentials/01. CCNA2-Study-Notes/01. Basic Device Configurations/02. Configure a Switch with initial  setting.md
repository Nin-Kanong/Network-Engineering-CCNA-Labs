### Switch Boot Sequence

## Cisco Switch 5-Step Boot Sequence

| Step | Process                      | Short Summary                                                           |
| ---- | ---------------------------- | ----------------------------------------------------------------------- |
| 1    | POST                         | Tests the CPU, DRAM, and flash memory to check hardware.                |
| 2    | Load Boot Loader             | Loads the boot loader program from ROM.                                 |
| 3    | CPU Initialization           | Initializes CPU registers and memory settings.                          |
| 4    | Initialize Flash File System | Prepares the flash file system for use.                                 |
| 5    | Load Cisco IOS               | Loads the IOS operating system into memory and transfers control to it. |


> ROM stores the POST and boot loader, flash stores the IOS image, and RAM holds the IOS while the switch is running.



### The boot system Command

The **boot system** command tells a Cisco switch which IOS image file to load when it starts.

Sample Command:
````
S1(config)# boot system flash:/c2960-lanbasek9-mz.150-2.SE/c2960-lanbasek9-mz.150-2.SE.bin
````

| Part                              | Meaning                                        |
| --------------------------------- | ---------------------------------------------- |
| `boot system`                     | Specifies the IOS boot image.                  |
| `flash:`                          | Storage device where the IOS files are stored. |
| `c2960-lanbasek9-mz.150-2.SE/`    | Directory containing the IOS image.            |
| `c2960-lanbasek9-mz.150-2.SE.bin` | IOS image filename.                            |

- BOOT environment variable: Tells the switch which IOS image to load.
- `startup-config` (`config.text`): Stores saved configuration settings in flash.
- `show boot`: Displays the current boot settings and IOS boot file.

> `boot system` selects the IOS image, while `show boot` checks the boot configuration.








### Switch LED Indicators

Cisco Catalyst 2960 switches use LEDs to show the switch's status, power, and port activity.

| No. | LED Indicator | Purpose                                                                  |
| --- | ------------- | ------------------------------------------------------------------------ |
| 1   | SYST          | Shows the overall system status.                                         |
| 2   | RPS           | Shows the status of the Redundant Power System.                          |
| 3   | STAT          | Displays port status, such as link and activity.                         |
| 4   | DUPLX         | Displays whether a port is operating in half-duplex or full-duplex mode. |
| 5   | SPEED         | Displays the port's operating speed.                                     |
| 6   | PoE           | Shows Power over Ethernet status, if supported.                          |
| 7   | Mode Button   | Changes what information the port LEDs display.                          |
| 8   | Port LEDs     | Show the status of individual switch ports.                              |

#### Common LED Colors

| LED Color / State | General Meaning                                                        |
| ----------------- | ---------------------------------------------------------------------- |
| Green             | Normal operation or active connection, depending on the LED mode.      |
| Blinking green    | Activity or data transmission, depending on the mode.                  |
| Amber             | A warning, fault, or blocked port, depending on the LED.               |
| Off               | Inactive, no connection, or feature not enabled, depending on the LED. |

> The same port LED can mean different things depending on which mode is selected. Always check the selected mode before interpreting the color.





### Recovering from a System Crash

The **boot loader** helps recover a Cisco switch when the IOS operating system is missing or damaged. It allows you to access flash memory and load a working IOS image.

| Step | Command / Action                               | Purpose                                       |
| ---- | ---------------------------------------------- | --------------------------------------------- |
| 1    | Connect console cable                          | Access the switch through a terminal program. |
| 2    | Unplug power                                   | Turn off the switch.                          |
| 3    | Hold the Mode button while powering on         | Enter the boot loader.                        |
| 4    | Wait for the LED indication, then release Mode | Access the boot loader prompt.                |
| 5    | `help` or `?`                                  | Display available commands.                   |
| 6    | `set`                                          | Check the BOOT environment variable.          |
| 7    | `flash_init`                                   | Initialize flash memory.                      |
| 8    | `dir flash:`                                   | List files stored in flash.                   |
| 9    | `BOOT=flash:c2960-lanbasek9-mz.150-2.SE8.bin`  | Set the IOS image to boot.                    |
| 10   | `set` then `boot`                              | Verify the boot path and load IOS.            |

#### Important boot loader commands

| Command                   | Meaning                                        |
| ------------------------- | ---------------------------------------------- |
| `help` or `?`             | Show available commands.                       |
| `set`                     | Display environment variables, including BOOT. |
| `flash_init`              | Initialize the flash file system.              |
| `dir flash:`              | List files and directories in flash memory.    |
| `BOOT=flash:filename.bin` | Set the IOS boot image path.                   |
| `boot`                    | Start the IOS image.                           |

- Boot loader: Provides recovery access when IOS cannot start.
- Flash memory: Stores the IOS image and configuration files.
- BOOT variable: Specifies which IOS image the switch should load.
- Console connection: Allows you to access the `switch:` prompt.

`Console → Mode button → set → flash_init → dir flash: → Set BOOT → boot`

> **Note**: The example filename must match the actual IOS image in flash. These commands are specific to the boot loader environment; `BOOT=...` is not a normal Cisco IOS configuration-mode command.








### Switch Management Access

To manage a Cisco switch remotely, we need to configure an SVI (Switch Virtual Interface) with an IP address and subnet mask.

- **SVI**: A virtual interface used to manage the switch; it is not a physical port.
- **IPv4**: Requires an IP address and subnet mask.
- **IPv6**: Requires an IPv6 address and prefix length.
- **Default gateway**: Allows the switch to communicate with management devices on other networks.

### Example Cisco configuration

```
Switch> enable
Switch# configure terminal
Switch(config)# interface vlan 1
Switch(config-if)# ip address 192.168.1.2 255.255.255.0
Switch(config-if)# no shutdown
Switch(config-if)# exit
Switch(config)# ip default-gateway 192.168.1.1
```

### Key points

| Command              | Purpose                                                 |
| -------------------- | ------------------------------------------------------- |
| `interface vlan 1`   | Enters the VLAN 1 virtual interface.                    |
| `ip address`         | Assigns an IPv4 address and subnet mask.                |
| `no shutdown`        | Enables the interface.                                  |
| `ip default-gateway` | Sets the gateway for remote management across networks. |

Remember: The switch's management IP identifies the switch on the network, while the default gateway allows management traffic to reach other networks.

Note: VLAN 1 is used here as an example. The SVI also requires the VLAN to exist and have an active port for it to become operational. Remote access additionally requires appropriate management services and security configuration.
